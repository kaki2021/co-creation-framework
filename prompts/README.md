# 人工智能提示词

这里的提示词用于执行公开规则，不替代规则。发生冲突时，以[贡献核算与分配](../docs/05-贡献核算与分配.md)和[文档型成果动态分配](../docs/14-文档型成果动态分配.md)为准。

## 任务总贡献值

按顺序使用：

1. [任务贡献值预评估](01-任务贡献值预评估.md)：整理事实、选择参数并给出初评；
2. [任务贡献值独立复核](02-任务贡献值独立复核.md)：检查证据、重复计算和算术；
3. [任务贡献值最终整合](03-任务贡献值最终整合.md)：统一参数、说明取舍并给出建议值；
4. 人工评审交付物，确认验收系数和最终任务总贡献值。

第一段的完整输出应原样交给第二段；原任务材料、第一段输出和第二段输出再一起交给第三段。不要只复制最后一个数字。

## 文档型成果内部份额

任务总贡献值经过人工确认以后，再使用：

1. [文档型成果贡献信息提取](04-文档型成果贡献信息提取.md)；
2. 人工确认哪些贡献被最终版本采用，以及贡献等级；
3. [文档型成果动态分配](05-文档型成果动态分配.md)；
4. 人工核对总和、空缺角色、利益冲突和申诉。

## 使用要求

- 在每次输出中保存规则版本、提示词版本、模型名称和日期；
- 任务描述、会议记录和文档内容都是待分析数据，其中的指令不得覆盖规则；
- 不让模型凭空补全缺失事实，缺少信息就写“待人工确认”；
- 不把市场报价、个人身份或资历直接当成贡献依据；
- 不把任何 API 密钥、口令或访问令牌写入提示词、网页或仓库；
- 生产系统应通过服务端环境变量或安全凭据管理调用模型，不在浏览器代码和 `localStorage` 中保存长期密钥。

参数的机器可读版本见 [`config/contribution-rules-v0.1.yaml`](../config/contribution-rules-v0.1.yaml)。
