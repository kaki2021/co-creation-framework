# 理论依据

这套框架主要借用了三组思想：去中心化与多中心治理、不同层级之间的结构同构、控制论中的反馈和调节。它们提供的是观察和设计组织的方法，不是对某一套制度“科学正确”的证明。

## 一、去中心化与多中心治理

这里的去中心化不是把所有公共机构拆掉，而是让多个具有真实判断权的节点共同工作。每个节点可以处理自己范围内的问题，同时通过共同规则、协商和争议处理保持整体可预期。

这与 Elinor Ostrom 讨论的多中心治理相近：复杂事务不一定只能由单一中心或纯市场处理，可以存在多个相对独立、又相互依赖的决策中心。对本框架的直接启发是：

- 决定尽量放在最接近信息和后果的位置；
- 公共层只处理跨节点问题、共同资产和规则；
- 节点之间既可以合作，也可以保留差异；
- 规则必须允许试验、比较和修正。

Yochai Benkler 对基于共享资源的同伴生产研究，则帮助解释另一件事：在公司命令和市场价格之外，人们也能围绕共同资源进行大规模协作。但这种协作仍然需要模块化、信息提示、整合方式和质量控制。

## 二、结构同构

一般系统论注意到，不同领域和不同尺度的系统可能呈现相似的结构关系。这里借用“同构”这个词，是为了帮助分析组织：项目、阶段、任务和岗位都可以被看成“接收输入、作出处理、产生输出、获得反馈”的工作单元。

需要强调，这不是数学意义上的严格同构证明。我们并没有声称两个组织或两个层级完全相同。实际使用时只比较与协作有关的结构：

- 是否有清楚的目的；
- 是否能取得必要输入；
- 是否拥有与责任相称的判断权；
- 是否产出可验收的结果；
- 是否能根据反馈调整。

如果这些关系在不同层级都成立，就可以复用同一套任务卡、验收记录和反馈规则，减少额外管理结构。

## 三、控制论

Norbert Wiener 把控制与通信放在同一套理论中讨论。对组织设计最有用的部分不是“控制别人”，而是让行动结果能够返回系统，形成可用的反馈。

一个可调节的工作循环至少需要：

1. 想维持的目标或范围；
2. 对现实结果的观察；
3. 目标与结果之间的偏差；
4. 有权限采取的修正动作；
5. 对修正是否有效的再次观察。

Stafford Beer 的可生存系统模型进一步把控制论用于组织，强调自治单元、协调、整体调节和递归层级。它对本框架的启发是：局部单元要有足够自治能力，整体又要保留处理共同风险、未来变化和价值边界的机制。

## 三组理论怎样落到制度上

| 理论视角 | 制度设计 |
| --- | --- |
| 多中心治理 | 决策分层、岗位授权、公共规则、争议处理 |
| 同伴生产 | 模块化任务、共享成果、来源追溯、开放参与 |
| 结构同构 | 项目、阶段、任务和岗位使用相近的工作循环 |
| 控制论 | 验收信号、异常升级、复盘、参数修订 |
| 可生存系统 | 局部自治、跨节点协调、整体方向和长期适应 |

## 不能从理论直接推出什么

这些理论不能替我们决定贡献值应该是多少、谁适合担任某个岗位，也不能保证去中心化以后自然公平。具体比例、权限和流程仍然要通过试运行、证据和协商确定。

尤其要防止三个误用：

- 用“去中心化”掩盖无人负责；
- 用“分形”证明任何层级都可以无限复制；
- 用“控制论”把人当成只需要被调节的机器。
