# 节点自主执行

这里的“自主”指成员在自己承担的工作节点中作出判断、完成交付并根据反馈调整，不是给某个岗位无限的决定权。

## 自主的起点是说清自己

成员参与协作时，先说清自己的目标、能力、需求和可用时间。团队只有知道每个人可以承担什么、当前有多少精力，才能安排真实可行的合作。

清楚表达自己的边界，不等于只顾自己。它是为了减少错误预期，也让其他成员知道何时可以依赖这个节点。

## 每项工作都是网络中的一个节点

一项具体工作至少需要说清四件事：

| 项目 | 需要说清的内容 |
| --- | --- |
| 输入 | 这项工作依赖哪些上游材料或结果 |
| 处理 | 承担者要调研、分析、判断和完成什么 |
| 输出 | 最终交付什么成果 |
| 下游 | 哪些工作会继续使用这份成果 |

承担者需要理解上游成果，也要确保自己的输出能被下游继续使用。所以节点自主不是各自完成一份孤立工作，而是在明确的连接关系中负责自己的一段。

## 执行本身包含局部规划

复杂任务可以继续拆分，但每个小任务不只是被动执行一条指令。它本身也包含一个小循环：

1. 调研需要处理的问题；
2. 分析已有材料和限制；
3. 在任务范围内作出判断；
4. 形成可以交给下游的成果。

这就是“执行即规划”。宏观方向由项目共同维持，具体节点的处理方式由最了解它的成员调整和优化。

## 自主执行的边界

节点内的具体判断可以由承担者完成；会影响其他成员的行动，先与相关成员沟通；重要方向和共同规则的变更，交给集体讨论和表决。

这条边界同时保留了两件事：成员不需要为每个局部判断等待上级，个人也不能把自己的决定强加给整个团队。

## 从执行者到负责人

成员可以从承接事项开始，逐步承担任务拆解、项目发起和团队统筹。负责人轮换后，再以副职或顾问身份把经验交给新的负责人。

这部分的完整路径见[成员成长与岗位轮换](11-成员成长与岗位轮换.md)。
