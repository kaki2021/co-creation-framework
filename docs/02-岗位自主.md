# 岗位自主

自主不是一句态度，而是一组可以检查的条件。一个岗位如果只有责任，没有权限、信息和资源，就不是真正自主；如果只有权限，没有边界和验收，也无法与其他岗位稳定合作。

## 一个自主岗位必须说清楚九件事

| 项目 | 要回答的问题 |
| --- | --- |
| 目的 | 这个岗位长期要保证什么结果 |
| 输入 | 开始工作前需要收到哪些信息或材料 |
| 输出 | 必须交付什么，交给谁 |
| 权限 | 哪些决定可以自行作出 |
| 资源 | 可以使用哪些预算、工具、数据和人力 |
| 边界 | 哪些事情明确不能自行决定 |
| 验收 | 什么条件下算完成或达标 |
| 反馈 | 用什么信号判断工作是否有效 |
| 升级条件 | 遇到什么情况必须求助或提交共同决策 |

这九项构成岗位的工作契约。它不是劳动合同，也不是固定不变的职位说明，而是协作接口。

## 自主权应当和影响范围相称

| 决定类型 | 通常由谁决定 | 示例 |
| --- | --- | --- |
| 局部且可撤回 | 执行岗位 | 工作顺序、工具选择、局部表达 |
| 影响相邻岗位 | 相关岗位协商 | 接口变化、交付时间调整、共享素材修改 |
| 影响整个项目 | 项目共同决策 | 主线方向、重要预算、对外承诺 |
| 改变公共规则 | 治理程序 | 贡献算法、知识产权规则、成员权利 |

自主权不是按头衔一次性授予，而是跟随工作范围。范围扩大时，说明和复核也要随之增加。

## 岗位怎样保持活性

### 主责与副手

每个关键岗位都应有主责人和能够接手的副手。副手不是永远的助手，而是在参与中掌握完整上下文。这样可以减少单点依赖，也为岗位轮换做准备。

### 发起人与守护人

新项目可以由一个人发起，但不应永远由发起人控制。项目进入稳定阶段后，发起人的角色应逐步从“事事决定”转为“守护最初目的、解释历史背景、帮助新人接手”。

### 岗位轮换

轮换不是定期把所有人换一遍。适合轮换的是容易形成信息垄断、长期消耗或需要培养接班人的岗位。专业连续性很强的岗位可以长期任职，但必须有文档、备份人和复核机制。

## 什么时候必须升级处理

出现以下情况时，岗位不应独自承担：

- 目标之间发生冲突，现有规则无法判断优先级；
- 需要改变其他岗位已经确认的接口；
- 将使用超出授权范围的公共预算或知识产权；
- 决定难以撤回，可能造成长期声誉、法律或安全风险；
- 反馈持续异常，岗位自己无法恢复；
- 当事人同时是执行者、验收者和主要受益者，存在明显利益冲突。

把升级条件提前写清楚，比出了问题再追责更重要。

## 自主不等于孤立

每个岗位都应能独立完成自己的闭环，但不需要成为一个缩小版的全能团队。岗位之间通过清楚的输入和输出连接。遇到超出范围的问题时，能够及时请求支持，本身也是自主能力的一部分。
